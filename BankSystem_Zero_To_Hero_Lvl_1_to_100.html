Level 1–20: The Physical Bank Analogy

Understanding software by comparing it to a real-world bank you visit in person.
Tier 1: Novice
How Software Mirrors a Real Bank

Imagine you want to transfer $100 to a friend in the real world. You don't walk into the bank vault and grab cash yourself—that would be chaotic and illegal! Here is how a real bank operates, and its exact 1:1 software counterpart in BankSystem.Web:

1. The Customer

You arrive at the bank and want to make a transfer, check your balance, or apply for a loan.

Software = The Web Browser (Chrome/Edge)

2. The Security Guard at the Door

Checks your ID card. If you are not a verified bank customer, you are stopped at the door.

Software = [Authorize] Middleware & Cookies

3. The Bank Teller at the Counter

Greets you, hands you a transfer slip, verifies what you wrote on it, and talks to back-office workers.

Software = MVC Controller (TransactionController)

4. The Paper Transfer Slip

A standardized form where you write: "From Account", "To Account", "Amount". Must be positive!

Software = ViewModel (TransferViewModel)

5. The Back-Office Vault Officer

Checks if you actually have enough money in your account, handles the math, and logs the change.

Software = Business Service (TransactionService)

6. The Vault & Official Ledger Book

The permanent, locked steel vault and master ledger where balances are stamped and recorded permanently.

Software = EF Core (ApplicationDbContext) & SQLite
Level 10: The MVC (Model-View-Controller) Pattern

ASP.NET Core uses the MVC pattern to separate duties cleanly:

M - Model

Represents the Data.
Examples in our code: Account, Customer, Transaction, Loan.

V - View

The visual HTML Webpage that the user sees in their browser.
Examples: Dashboard.cshtml, Transfer.cshtml.

C - Controller

The Brain / Traffic Cop.
Receives HTTP requests, calls services, and decides which View or Redirect to return.

Tier 2: Apprentice
Level 30: Why ViewModels? (Over-Posting Attacks Explained)

Why don't we pass the database model Account directly into the transfer form?

Bad (Novice Mistake)

Accepting Account directly in the controller action: 

public IActionResult Update(Account account)
{
    // DANGER: An attacker can send a POST request with
    // "Balance=99999999" and the framework binds it!
}
Good (Senior BankSystem Pattern)

Using a dedicated TransferViewModel: 

public class TransferViewModel
{
    [Required]
    public int FromAccountId { get; set; }
    
    [Required]
    [Range(0.01, double.MaxValue)]
    public decimal Amount { get; set; }
}

Protection: ViewModels act as a strict whitelist. The user can only submit what we explicitly define. [Range(0.01, ...)] ensures nobody can transfer negative money to steal from an account!

Tier 3: Journeyman
Level 50: Deferred vs Immediate Execution in LINQ

One of the biggest concepts in .NET is that LINQ queries are lazy (deferred):

ReportController.cs - LINQ Query
// STEP 1: Builds the SQL query in memory (NO DATABASE HIT YET!)
var query = _context.Transactions
    .Where(t => t.AccountId == accountId && t.Amount > 100)
    .OrderByDescending(t => t.TransactionDate);

// STEP 2: The moment ToListAsync() is called, SQL is sent to SQLite!
var results = await query.ToListAsync();

Why this is awesome: You can chain 10 different filters (.Where(), .Take(5), .OrderBy()) without running multiple queries. EF Core merges all of them into a single, highly optimized SQL query!

Level 55: The N+1 Query Bug & Eager Loading (.Include)

Suppose you have 100 customers and each customer has accounts.

Without .Include (N+1 Query Bug)

Loads 1 query for customers, then fires 100 separate queries to fetch accounts for each customer: 101 database queries total! Server slows to a crawl.

With .Include (BankSystem Way)

_context.Customers.Include(c => c.Accounts) fires EXACTLY 1 QUERY using a SQL LEFT JOIN. 100x faster!

Level 70: ACID Database Transactions

What happens if John transfers $500 to Mary, John's account is deducted $500, and right at that microsecond the server crashes before Mary is credited?

The Nightmare Scenario: $500 vanished into thin air! John lost it, but Mary never received it!

In [TransactionService.cs](file:///c:/Users/mahmoud%20hazem/Desktop/BankSystem/BankSystem.Web/Services/TransactionService.cs#L31), we enforce ACID Atomicity: 

using var transaction = await _context.Database.BeginTransactionAsync();
try {
    fromAccount.Balance -= model.Amount; // Step 1
    toAccount.Balance += model.Amount;   // Step 2
    await _context.SaveChangesAsync();
    await transaction.CommitAsync();     // Both commit together
}
catch {
    await transaction.RollbackAsync();   // If anything fails, revert completely!
}

Tier 5: Architect
Level 90: The Double-Spending Race Condition Attack

Suppose a user has $100 in their checking account. They open two browser tabs at the same time and hit "Transfer $100" simultaneously in both tabs at the exact same millisecond:

Thread 1: Reads Balance ($100). Checks if ($100 >= $100) → YES!
Thread 2: Reads Balance ($100). Checks if ($100 >= $100) → YES!
Thread 1: Deducts $100 → Balance becomes $0.
Thread 2: Deducts $100 → Balance becomes -$100 (or overwrites with $0)!
Result: $200 was transferred out of an account that only had $100!
The Enterprise Fix: Optimistic Concurrency Token

Add a concurrency token to the Account model: 

[Timestamp]
public byte[] RowVersion { get; set; }

When Thread 1 saves, the database changes the version from 1 to 2. When Thread 2 tries to save with version 1, EF Core throws a DbUpdateConcurrencyException and rejects the duplicate transaction automatically!

Level 100: The 1,000,000+ User Cloud Architecture

To scale from a local SQLite starter to a global high-availability banking platform:

PostgreSQL Cluster

Primary write node with multi-region read replicas. Read-heavy operations (viewing transaction history) hit replicas, while writes (transfers) hit the primary node.

Redis Distributed Cache

User session cookies and customer profiles are cached in Redis in-memory with sub-millisecond latency. Reduces database reads by up to 80%.

RabbitMQ / Kafka

Asynchronous event bus for sending email alerts, fraud detection scoring, and statement PDF generation without blocking the user's transfer request.
